# Files {#files}

The folders nest as the data does, one class per file, the file name spelling the path down the tree. Algorithms live apart from the data they produce and are named by what they produce.

| Folder or file | Holds |
|---|---|
| `wood_settings` | `Settings`, every tunable the solver reads, filled from the dataset yml, held by the scene, written with the file |
| `wood_config` | the dataset catalogue and the paths, `load_yaml` |
| `wood_elements/` | one element class per file, all derived from `session_cpp::Element` |
| `wood_interaction/` | the interaction tree: contact, feature, structure, one class per file, folders nested as the data |
| `wood_interaction_feature_plate_joints/` | one header per joint variant, plus `custom_outlines`, `tt_e_p_drills`, `cr_c_ip_core`, `ss_e_r_core` for code several joints share |
| `wood_algorithms/` | detection, construction, the solver pipeline and the registry, three-valence, merge, assignment |
| `wood_session` | the scene, the store, the pipeline entry points |
| `wood_view`, `wood_io`, `wood_serialization`, `wood_test` | viewer layout and colours, readers and parity dumps, JSON from proto, the dataset runners |
| `proto/`, `generated/` | one protobuf message per class and the committed C++ output, regenerated by `tools/regen_proto.sh` |
